# 演示脚本（3 分钟，无需改代码）

> 目标：让看的人在前 40 秒内明白「这不是又一个 ChatGPT 套壳」，
> 并在第一分钟看到**视频面试**这个别人没有的东西。

## 演示前 5 分钟的准备

```bash
# 1. 后端
cd backend && python -m uvicorn app.main:app --reload --port 8000

# 2. 前端
cd frontend && npm run dev        # 必须用 http://localhost:5173
# 注意：浏览器只在 localhost 或 https 下允许访问摄像头，用局域网 IP 会被拒绝

# 3. 准备材料（提前放在桌面）
#    - 一份真实简历 PDF（建议含 1-2 个有数字的项目）
#    - 一段真实岗位 JD 文本
```

**提前做三件事**：

1. **预跑一场完整面试**并生成报告，演示时随时可以切过去兜底（防现场网络/API 抖动）。
2. **在浏览器里提前授权过摄像头**，避免演示时弹出权限框打断节奏。
3. **关掉腾讯会议 / 钉钉 / OBS** —— 它们占用摄像头会导致 `NotReadableError`。

---

## 0:00–0:20 · 说清定位（不看屏幕，先给结论）

> "秋招面试最难受的地方是：**练习机会太少，而且没有反馈**。投十家面三家，
> 面完只收到感谢信，不知道自己哪句话说错了。
>
> 直接问 ChatGPT 也不行 —— 它不会追问、不会压时间、不会打分、不会留复盘记录，
> 更不会让你看到**自己答题时的样子**。
>
> 所以我做了这个：打开摄像头，面对六个不同风格的面试官，练一场会追问的视频面试。"

---

## 0:20–0:50 · 设备检测（体现"真实视频面试"）

1. 打开 `/interview/setup`，**选「视频面试」**，选简历 + JD，开始。
2. 进入**设备检测**页。指着屏幕说：

> "注意这一步 —— 真实视频面试平台都有设备检测，因为'面试官都能看到你了、
> 你才发现麦克风没开'是最糟的开场。"

3. 指几个细节：
   - **麦克风音量条** → "对着麦克风说句话，音量条会动。静音的话这里不会有反应。"
   - **摄像头/麦克风下拉框** → "可以切换设备，比如笔记本外接的麦克风。"
   - **坐姿建议** → "镜头与眼睛齐平；**看着镜头，不是看着屏幕上的自己** —— 这两条是真实视频面试的常见失分点。"

---

## 0:50–1:10 · 面试官安排（体现"多轮换人"）

4. 回到配置页（或提前截图），指面试官分配表：

> "六个环节由**六位不同面试官**负责。这不是换个名字 —— 提问口径和评分侧重都会变。
> HR 关心动机，技术主管关心你到底做了什么，技术专家关心原理，终场面试官专门质疑你的数据。"

5. 如果时间够，点开一位面试官的"了解这位面试官"：

> "每个人格都有真实的背景和提问风格，这些会真的进入提示词。"

---

## 1:10–2:10 · 面试进行（核心，体现"自适应追问"）

点开始 → **3-2-1 倒计时** → 面试官**语音**读出问题，右侧面板显示说话波形。

### 第一题（自我介绍）—— 故意用空泛回答

对着麦克风说：

> "我大学期间做过几个项目，主要做后端开发，参与了一些接口优化工作，性能提升比较明显。"

提交后，等面试官追问，此时说：

> "看 —— 我说了'提升了性能'但没给数字，它**没有放过我**，而是追具体案例。
> 这是提示词里'空泛 → 追具体案例'的规则。而且它是**听出来的**，我只是口述。"

### 第二题（专业技能）—— 这次给数字

> "我给订单表加了 (user_id, status) 的联合索引，P99 从 800ms 降到 120ms，QPS 提升到 3000。"

等追问出现：

> "注意它追的是**我说的那个数字的来源**：怎么测的、对比基线是什么。
> 这是另一条规则：有数字就必须追一层。"

### 顺带指三个界面细节

- 顶部只有**进度条和剩余时间**，**没有任何分数** → "面试过程中不给分数，这是故意的：看到分数人会分心去猜评分标准，就不像在面试了。"
- 右上角**自视窗**有 REC 角标和录制计时 → "你的画面正在本地录制，**不上传服务器**。"
- 点一下「暂停」→ "暂停时间不计入面试时长 —— 否则这个按钮就是坑你的。"

---

## 2:10–2:50 · 报告（体现"可解释评分 + 录像回放"）

（时间紧就直接切到预跑的报告）

1. **结论卡 + 五维雷达图** → "五维权重固定：相关性 20%、结构 20%、深度 25%、表达 15%、匹配 20%。"
2. **重点讲表达实测** —— 这是最能体现"真实视频面试"的部分：

> "这一块不是模型猜的。它从我的录音里算出**语速、口头禅占比、长停顿次数** ——
> 你看这里：语速 207 字/分钟在正常区间，但口头禅占了 7%，所以表达只有 3 分。
> 这些数字是可以核对的，不是'我觉得你表达不太流畅'。"

3. **讲证据引用** —— 展开任意一题，指「评分依据（引用你的原话）」：

> "每一道题的分数，都必须引用我的**原话**作为依据。这是提示词里的硬性要求 ——
> 它不能凭空说'回答比较空泛'，必须先找到我说过的那句话。"

4. **讲录像回放** —— 点开某一题的播放器：

> "这是我自己那一题的回答。**很多人第一次看到自己的录像，才发现'我以为我很镇定，
> 其实一直在抖腿 / 眼神乱飘 / 语速飞快'。** 这是文字面试永远给不了的东西。"

5. **讲"下一步会被追问什么"**：

> "这一块比'这题答得不好'更可操作 —— 它告诉你**就凭这句话，面试官下一句会打哪儿**。"

6. **讲参考答案的占位符**（如果开了练习模式）：

> "缺数据的地方它会留占位符，让**我自己**去补，而不是替我编一个漂亮的数字。
> 编数据等于教学生编简历。"

---

## 2:50–3:00 · 收尾（主动说缺点，反而加分）

> "最后说说短板，我很清楚：
>
> 第一，**评分一致性没有做人工标注集校准**。所有防偏置手段都是设计上应该有效，
> 但没有实测'AI 打分和人工打分的相关性'。下一步是取 20 份真实问答人工打分算相关系数。
>
> 第二，**录像只存本地**，换设备就看不到 —— 这是我为了'录像永远不泄露'做的取舍，
> 报告里也明确写了。真要跨设备看回放，就得建对象存储 + 权限体系，那是另一个量级的工程。
>
> 第三，**没有并发压测**。SSE 长连接 + 单进程 uvicorn 的承载上限我还没有数据。
>
> 它现在最适合解决的，是**结构和表达**层面的问题 —— 尤其是'你以为讲清楚了、
> 面试官却听不出你的贡献'这种。技术正确性还得自己把关。"

## 现场可能被问到的技术问题（备答）

| 问题 | 一句话回答 |
|---|---|
| 追问逻辑怎么实现的？ | 不是靠提示词，是服务端纯函数规则（数字必追、空泛必追、同点最多 2 层），29 个单测覆盖边界。 |
| 视频是怎么做的？ | 原生 `getUserMedia` + `MediaRecorder` + Web Speech API + IndexedDB，零依赖。三个自研 hook 保证 ASR 和录制的时间轴对齐。 |
| 录像存在哪？ | 只存浏览器 IndexedDB，服务端只记一个 key。用"换设备看不到"换"永远不会泄露"。 |
| 语速怎么算的？ | 词数 / 录制时长；长停顿是相邻 ASR 结果超过 2.5 秒。是启发式的，不是声学分析 —— 但足够抓住"太慢/口头禅多/卡壳"。 |
| 为什么让 LLM 输出纯文本而不是 JSON？ | JSON 没法边生成边用，流式会退化成假的；决策拿回服务端后，既真流式又可测试。 |
| 评分怎么防止瞎打？ | 出题与评分拆成两次独立调用（不同温度/角色）+ 固定锚点 + 强制引用原话 + 语音时以实测数字为准。 |
| 没有数据会不会编？ | 不会。纯文字作答时提示词里明确写"没有语速数据，不要臆测"；参考答案缺事实时留占位符。 |
| 上下文太长怎么办？ | 近 4 轮全文，更早轮次压成一行摘要；token 用量落库可观测。 |
| 为什么用 SSE 不用 WebSocket？ | 严格一问一答，单向流式足够；实现简单、容错成本低、穿透代理更稳。 |
| 断了网怎么办？ | 服务端 `finally` 里落库已生成内容；未完成的评分转后台用独立会话写入；前端有恢复接口 `POST /next`。 |
| 换面试官有什么意义？ | 人格同时改变提问口径与评分侧重。真实校招就是多轮的，只练一个面试官等于只练一种问法。 |
| 参考了 JobPilot 什么？ | 人格库、单题评分卡、回合状态机、占位符纪律、反 AI 腔护栏。**没有复制代码**，且它没有音视频能力。 |
| 没有 API Key 能演示吗？ | 能。内置 Mock 面试官是规则引擎，会真解析、真追问、真打分、真算表达指标，全流程可跑通。 |

## 演示时不要做的事

- ❌ 不要用局域网 IP 打开前端（浏览器会拒绝摄像头）
- ❌ 不要开着腾讯会议/钉钉/OBS（会占用摄像头导致 `NotReadableError`）
- ❌ 不要在面试进行页找分数（那里故意没有）
- ❌ 不要说"AI 打分很准" —— 说"可解释、可自查"更站得住
- ❌ 不要现场改代码或装依赖
- ❌ 不要承诺用户量/上线情况等没有的数据
